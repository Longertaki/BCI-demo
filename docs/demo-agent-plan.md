# Demo 框架 · 子任务 Agent 调度计划

> 版本：v0.1 ｜ 状态：规划草稿
> 目标：用「监督者 + 执行者 + 测试者」的多 agent 结构，实现袖里乾坤的 Demo v1 框架（不接 LLM、不接真实手环）。

---

## 1. Demo v1 范围

**最小可玩闭环**：键鼠活跃度（模拟）→ 气运流转 → 侠客闯荡 → 产出盲盒 → 开箱 → 门派经营（技能/被动收益/商城）。

明确**不做**（后续阶段）：
- 真实 EMG 手环接入（v1 用键盘活跃度 + 模拟信号）
- Qwen 本地模型 NPC 互动（v2）
- 真实市场玩家间交易（v1 只做钱币商城 + 简化行情）

---

## 2. 角色分工

| 角色 | 谁 | 职责 |
|------|----|------|
| **监督者** | 父 agent（我） | 拆分任务、定义接口契约、审查产出、集成、决策 |
| **执行者** | 4~5 个并行子 agent | 各实现一个模块 |
| **测试者** | 1~2 个子 agent | 单元/集成测试、玩法循环 smoke test、数值 sanity check |

---

## 3. 模块划分与接口契约

| 模块 | 执行者 | 职责 | 输出接口 |
|------|--------|------|----------|
| M1 数值配置 | E1 | 参数表 + 成长曲线函数 | `config/*.json` + `core/balance.py` |
| M2 信号采集 | E2 | 键盘活跃度采集 + 模拟信号源 | `活跃度因子(0~1)` 流 |
| M3 核心世界模拟 | E3 | 气运流转、侠客/门派状态、闯荡、Boss、时间推进 | 世界状态 + 事件流 |
| M4 经济系统 | E4 | 累计收益、盲盒开箱、钱币商城、门派资源、秘籍/装备 | 资源账本 + 交易 API |
| M5 桌宠 UI | E5 | 桌面角落窗口、世界可视化、菜单 | 展示 + 鼠标菜单交互 |

**依赖关系**：
- M1（配置）是地基，所有模块依赖它 → **先落地接口，再并行**。
- M2 → M3（活跃度喂给世界模拟）。
- M3 → M4（世界产出事件 → 经济结算）。
- M3/M4 → M5（UI 展示状态 + 菜单操作）。

---

## 4. 调度流程（分阶段）

### 阶段 0：监督者定契约（我先做）
1. 写 `docs/demo-contract.md`：定义各模块的输入/输出/数据结构/验收标准。
2. 搭好项目目录骨架（`demo/` 下分模块目录 + `config/`）。

### 阶段 1：并行执行（spawn 子 agent）
- 并行 spawn：E1(配置) → E2(信号) → E3(核心) → E4(经济) → E5(UI)。
- 各执行者只依赖「契约 + 骨架」，写自己的模块 + 自测。
- 完成一个模块 → 用 `agent_message` 回复监督者「完成 + 文件路径 + 接口说明」。

### 阶段 2：测试（spawn 测试者）
- T1 做集成测试：把 M1~M4 串起来，跑「挂机 → 闯荡 → 掉落 → 升级」循环。
- T2（可选）做数值 sanity：跑模拟器，看曲线是否平滑、有无卡点/爆炸。

### 阶段 3：审查与迭代（监督者）
- 我审查测试报告，定位问题，定向派单修复。
- 集成 UI（M5），做端到端 smoke test。
- 循环迭代直到闭环可玩。

---

## 5. 通信方式

- **代码/文档**：写到项目目录（`/home/alex/prime/Qiankun/demo/...`），通过文件共享。
- **接口约定**：写在 `docs/demo-contract.md`，执行者以此为准。
- **进度/问题**：子 agent 用 `agent_message.send(..., receiver_role='parent')` 回复监督者。
- **跨模块协作**：优先靠「接口契约 + 文件」，避免子 agent 之间直接消息依赖（降低耦合）。

---

## 6. 验收标准（Demo v1 完成定义）

1. 能模拟「键盘活跃度」驱动气运流转速度。
2. 侠客组队（≤3 人）自动闯荡，地区有难度差异，Boss 可选关挑战。
3. 掉落盲盒（秘籍/装备/丹药），开箱有稀有度（含保底）。
4. 累计收益自动积累 + 盲盒需手动开。
5. 门派资源可投入技能（倍率）与被动收益（基础设施）。
6. 钱币商城可买通用技能/基础装备。
7. 桌宠式 UI 常驻桌面角落，鼠标菜单可操作，手环指示灯（占位）。
8. 数值全部走配置表，可调。

---

## 7. 风险与注意

1. **接口先行**：没有契约就并行容易乱，阶段 0 一定要把数据结构定死。
2. **子 agent 数量**：5 个执行者 + 1 测试者较合适；再多协调成本高。
3. **子 agent 是并行的**：`rlm()` 只返回 admission，不等待结果，需要靠消息/文件收口。
4. **数值配置先行**：M1 的平衡参数是其他模块的地基，先出。
5. **demo 不追求完美数值**：先用方案 A/B/C 打底，D 模拟器做 sanity，后续再精调。
